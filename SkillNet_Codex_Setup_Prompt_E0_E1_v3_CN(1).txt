────────────────────────────────────────
三、A/B/C 冻结含义
────────────────────────────────────────

A：
- 平铺 Skills；
- 无部门嵌套；
- 无显式关系。

B：
- 与 A 完全相同的 Skill Cards；
- 按部门分组；
- 无显式关系；
- 部门分组只表示归属，不表示流程或顺序。

C：
- 与 B 完全相同的部门结构与 Skill Cards；
- 只额外增加显式 relations 和 relation semantics；
- department 不是父 Skill；
- C 中不存在 parent/children workflow 展开；
- Python 不参与 Skill 路由或修正模型答案。

同一 size 下必须验证：
- A/B/C Skill ID 集合一致；
- Skill Card 内容一致；
- B/C department grouping 一致；
- C 只比 B 增加关系；
- Catalogue hash 与 manifest 一致。

Catalogue 中的 `source_commit` 是冻结 source snapshot，不要求等于加入 Catalogue 后的新 repo commit。应核对 source hash/内容，不能只比较 commit 字符串。

────────────────────────────────────────
六、最小运行框架
────────────────────────────────────────

若 repo 没有更合理的现有结构，建立：

experiments/skillnet/
  RUNBOOK.md
  experiment_config.json
  run_condition.py
  verify_condition.py
  packets/
  runs/
  results/
  visualization_data/

只需要两个核心脚本：

1. `run_condition.py`
   - 接收 experiment、configuration、size、run_id；
   - 找到唯一正确的正式 Catalogue；
   - 为每题建立隔离 packet；
   - 每题启动一个全新的 `codex exec` 或当前 CLI 支持的等价独立进程；
   - 默认串行；
   - 支持 resume；
   - 不覆盖已有输出；
   - 不修复错误 JSON。

2. `verify_condition.py`
   - schema validate；
   - 组装 predictions.jsonl；
   - 调用现有 deterministic evaluator；
   - 生成核验结果、evaluation trace、graph overlay 和 tidy data；
   - 输出用户可独立复制执行的 evaluator 命令。

可以增加一个很小的共享 helper，但不要过度拆分脚本。

────────────────────────────────────────
七、实验隔离
────────────────────────────────────────

每个 child Codex 必须从独立 packet 目录启动，而不是 repo root。

packet 只能包含：

1. 一条中文任务；
2. 当前唯一 Catalogue JSON；
3. 固定输出说明；
4. 不泄露答案的 metadata。

不得包含：

- Gold；
- evaluator；
- review；
- Run Guide；
- `.agents/skills/`；
- 根目录 relation 文件；
- 独立裁剪 relation 文件；
- 其他 Catalogue；
- 其他 task；
- 之前结果；
- symlink 或返回 repo 的路径。

若本机存在全局 Codex Skills、插件或用户级指令，检查它们是否会污染实验。优先使用隔离的临时 `CODEX_HOME` 或 CLI 实际支持的等价方式；若无法隔离，明确报告，不要假装不存在。
